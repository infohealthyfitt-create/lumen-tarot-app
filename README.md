# LumenTarot

A worldwide Tarot-inspired guidance web application. Built with Next.js (App
Router, TypeScript), Tailwind CSS, Supabase (Auth + Postgres + RLS), and a
provider-agnostic Stripe payment layer. Deployed on Netlify.

> Positioning: *"Tarot-inspired guidance, reflection, and entertainment."*
> The app never presents readings as guaranteed predictions or as medical,
> legal, financial, or professional advice — see `src/data/safety-copy.ts`.

## Quick start (local development)

```bash
npm install
cp .env.example .env.local   # fill in what you have; see below
npm run dev
```

The app is designed to run **with zero external services configured**:

- No Supabase keys → the app runs anonymously; auth/dashboard shows a
  friendly "coming soon" state instead of erroring.
- No Stripe keys / `ENABLE_PAYMENTS=false` (default) → the premium upsell
  button shows a clean "not yet available" message instead of erroring.
- `ENABLE_AI_READINGS=false` (default) → all readings are generated by the
  local `TemplateReadingEngine` (no external API calls, no cost).

## Project structure

```
src/app/                     Routes (App Router)
src/components/               UI components
src/lib/tarot/                Deck data, types, randomization, reading engine
src/lib/payments/             Payment provider abstraction + Stripe impl + pricing config
src/lib/supabase/             Browser / server / service-role Supabase clients
src/data/                     Popular questions, safety copy, blog posts
supabase/schema.sql            Database schema
supabase/policies.sql          Row Level Security policies
scripts/generate_deck.py       One-time generator for the 78-card dataset
```

## Enabling Supabase (accounts, history, streaks, journal)

1. Create a Supabase project.
2. Run `supabase/schema.sql` then `supabase/policies.sql` in the SQL editor.
3. Set `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, and
   `SUPABASE_SERVICE_ROLE_KEY` (server-only) in your environment.
4. In Supabase Auth settings, add your site URL(s) to the redirect allow list
   (see `NETLIFY_DEPLOYMENT.md`).

## Enabling Stripe (premium readings)

1. Create Products/Prices in Stripe matching the IDs in
   `src/lib/payments/products.ts` (or update that file to match your Stripe
   Price IDs — it's the single source of truth for pricing).
2. Set `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`,
   `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`, and `ENABLE_PAYMENTS=true`.
3. Point a Stripe webhook at `/api/webhooks/stripe` (see
   `NETLIFY_DEPLOYMENT.md` for exact steps).

Premium access is only ever granted after the webhook verifies payment and
writes a `succeeded` row to the `payments` table — never from the
success-page redirect alone.

## Roadmap / what's scaffolded vs. fully wired

Fully working today: browsing flow, free 3-card readings (user-chosen
cards, no auto-pick), daily card + local streak, yes/no Tarot, love Tarot,
78 programmatic SEO card pages, blog, legal pages, checkout route + webhook
(inert until Stripe is configured), full DB schema + RLS.

Ready to wire up next: persisting readings/streaks to Supabase for signed-in
users (the tables and RLS already exist; `/api/readings` already returns
everything needed to write a row), an admin dashboard reading from the
`tarot_cards`/`products` tables, and real card artwork (currently stylized
placeholder card faces).
